3 月末，我打算将台式机的主力操作系统从 Win11 换到 linux。

从 Win 逃到 linux 的话题很常见，但我的情况又有不同。我有大量的 Windows 折腾经验：会调整注册表、改了右键菜单、会卸载自带软件、鉴别软件很在行...... 当时我用的是 Win11 24h2 第三方精简版，系统自身资源消耗不高且无更新。总之，我的 Windows 花过心思精心管理，并没有原版的臃肿和多数槽点。

我离开的原因主要包括：

- 在使用 Claude Code 等工具时明显感到 Windows 是二等公民。早在 AI 时代之前我就在用 Git Bash 环境，还研究着用上了 Zsh。但即便常见 cli 工具勉强得到支持，在 Windows 下的反斜杠路径也经常导致意外错误。WSL 的问题则是通过网络协议进行文件传输效率低，而我不希望工程文件存放在虚拟机中。
- AirPods 时常断联，不清楚是 Windows 24H2 的原因还是精简版的失误。
- 虽然在两年前换 mac 之前就在用 Win11，但还是感觉系统不太跟手，后来看到有 up 主解释了[原因](https://www.bilibili.com/video/BV11MVoznE4L/)。
- 在前些年扫盘事件后，我把微信装在了虚拟机中，但总有诸多不便。Linux 上或许有更好的办法。
- 当时基本不玩游戏，估量后认为基本没有 Linux 不能做的事情了。
- 新型的 Niri 窗口管理器很让我心动。
- 我很熟悉 Linux，虽不作日常系统，但在服务器用过很多年了。在命令和基础概念方面没什么学习成本。

于是在一个夜晚动手，我拥有了 Arch Linux + Niri。

虽然有服务器和 Ubuntu 桌面的经验，但这一番折腾确实接触到了新东西。我尝试理解一个桌面系统需要哪些组件，它们之间又是什么关系。对于每一种组件有哪些常见的选择，各选择之间又有哪些差异。像是在零件商店闲逛，然后组装出自己的武器。可能没什么技术含量，需要一点耐心，不过挺有趣的。最终我选择了 waybar + mako + foot + fuzzel 这一套主要组件，使用中逐渐完善它们的配置。

Niri 很棒，结合 foot 这个轻量的终端，让我感到命令行是思想的延伸。Mod + Enter 就像鼠标双击一样自然。

原生的 POSIX 环境也让 codex 可以完全接管从编程到系统配置的方方面面。在这个环境下我开始把之前略懂的 vim 作为主力，也发现了很多优秀的终端工具。可以说作为日常上网和开发的环境，这套环境轻量高效。

Arch 的应用生态也很棒。我只在不得不用时才考虑 AUR，但也够了。

我偶尔会切换回 Windows 玩英雄联盟，但这是可以割舍的部分。说到底我也不确定对这个游戏的态度，有时它是跟朋友同事的社交宝地，却也是虚度光阴最有效的麻醉剂。我尝试了 Steam，借着 Steam Desk 的东风，Linux 也吃上肉了。理论上很多游戏可以借助 Potron 无缝运行，但我简单跑了几个，要么分辨率配不好，要么手柄连击。Linux 上的游戏体验就像 Windows 上的终端体验，在一定的配置后可用，但总有割裂感。

我愉快地玩耍了两个月，事情的转机是我突然想学画画了。

板绘的主流软件原生不支持 Linux，而 Linux 上的 Krita 过于小众。或许通过虚拟机显卡直通或 Wine 有一定的办法，但这个任务的首要目标是稳定可靠而非折腾取乐。另一方面数位板虽可用，却没有驱动可以调节按键功能。于是我切到 Windows，安装 PS，点开浏览器放上音乐。再然后意识到已经有段时间没有回到 Linux 了。

目前的 Linux 的生态比起我在 2019 年左右首次尝试 Ubuntu 时好了太多。与 Windows 相比，系统本身轻量透明可配置、编程开发完胜，上网和单机游戏也持平甚至略胜 Windows。但涉及超出生态的工作还是会遇到麻烦，需要付出时间精力来折腾一个解决方案。即便用游戏心态对待折腾的过程，最后的方案也不保证稳定可靠。那么但凡上网编程和单机游戏不能完全覆盖你的活动，且你想把有限的精力投入到创作本身，Linux 就不太合适作为主力系统。

所谓抉择不是在好坏之间选择好的，而是两害相权取其轻。对我而言 Windows 的最主要问题是编程场景不顺手，而 Linux 则是难以支持主流绘画工作流。

那么最后，目前的情况如何呢？我删除了 Win11，安装了"小修精简版"的 Win10 22H2，并做了些配置，最终体验如下：

- 依然用 Git Bash 环境和 Zsh 作为终端，但换用 pi 作为编程智能体，经过自定义后也不太出错了。
- 主观上，动画响应比 Win11 好很多。
- 耳机、手柄和数位板都没问题了。
- 通过多账户隔离，在保证隐私的情况下正常用上了微信和 QQ。
- 用现代的手机厂商字体换掉了微软雅黑，很大程度改善了视觉体验。
- 得益于镜像作者的工作，系统无任何多余组件，无更新，资源占用与 Arch 差不多。

这又何尝不是"在否定之否定中螺旋上升"？Arch 还在我的硬盘上，到今天也很久没登录了，但一点点将其完善为趁手的工具过程，仍然让我十分怀念。谨以此贴留作纪念。
